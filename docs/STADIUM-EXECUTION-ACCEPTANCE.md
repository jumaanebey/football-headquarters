# Stadium execution — Codex implementation ledger

Scope: automatic execution after a call, moderate exaggeration, exactly two possessions with ties. This document tracks implementation, not a declaration that the complete experience is accepted. Claude owns the independent scenario gallery, acceptance harness and regression evidence; do not edit that package from this branch.

## This implementation

- Four defensive linemen engage blocker shoulders before shedding. Ends retain outside leverage.
- Three linebackers read before fitting gaps; the stacked front commits earlier. Two safeties retain depth before pursuit.
- Man defenders follow receiver routes. Zone defenders occupy underneath areas and deep halves before breaking on the throw.
- One defender finishes a stopped run; touchdown choreography leaves pursuit behind. Kick rush and kickoff coverage have separate paths.
- Slants, flood and verticals have stems and breaks. Two interior run blockers can climb to the second level.
- Failed pass presentation leaves the ball unsecured. It does not invent an interception or sack.
- Home defensive starters are named from the frozen lineup snapshot.

All paths render recorded results. No outcome rules, authority bundle, roster ratings, reward accounting or server operations change.

## Evidence and remaining acceptance

Local typecheck and 758 tests pass, including possession-direction symmetry, continuous dense trajectory samples, zone/man separation, stopped-run contact and touchdown separation. Full offline release verification is recorded separately in the delivery note. Native browser review uses the actual local reducer with no live account.

The larger milestone remains open until the independent gallery is reviewed across supported scenarios and viewports. Specifically: coverage handoffs are currently area-to-pursuit choreography rather than receiver-to-receiver handoffs; tackle art is a wrap pose rather than a full paired fall; ball flight and individual athletic identity need visual acceptance; crowd/sideline presentation remains simple. There are no new turnover/safety mechanics. These limitations must not be represented as completed features.
